# 手で進める試し（ChatGPT と Gemini を使う）

このページは、ディレクターが自分のパソコンで、2つのチャットアシスタントに交渉の手を考えさせ、ブラウザのページで進める手順です。署名と承認は、ページが模試の鍵でします。インターネットには出しません。

## 先に読むこと

- **ページに貼った文章と、チャットに貼った文章は、チャットの会社に渡ります。** ChatGPT なら OpenAI、Gemini なら Google です。
- **アシスタントに渡す文章には、その側の委任の限度が入っています。** 上限、下限、納期の限界、許す値です。それも会社に見えます。
- そのため、**作り話の仕事だけで試してください。** 実在の人、会社、連絡先、本物の金額、パスワード、鍵は、どこにも貼らないでください。
- ページの見本の仕事は、作り話です。そのまま使ってかまいません。
- 承認は、模試の人間の鍵でページがします。本物の承認アプリではありません。

## 用意するもの

- このリポジトリを置いたパソコン。
- ChatGPT と Gemini を開いたブラウザの画面を、2つ。依頼者用と受注者用です。同じ会話に混ぜないでください。

## 1. ページを作って開く

リポジトリの場所で、次の2つを順に実行します。

```bash
pnpm install --frozen-lockfile
```

```bash
pnpm build:browser
```

`artifacts/browser/ix-trial.html` ができます。これをブラウザで開きます（ファイルをブラウザにドラッグしても開けます）。サーバーは要りません。ページは通信をせず、何も保存しません。

ページを閉じる、または再読み込みすると、鍵も交渉の状態も消えます。やり直したいときは、再読み込みしてください。

## 2. 委任（限度）について

このページには、委任を入力する画面はありません。見本の仕事に合わせた、次の限度が最初から入っています。値を変えたいときは、コードを直す作業になるので、エンジニアに頼んでください。

| 項目 | 依頼者の限度 | 受注者の限度 |
| --- | --- | --- |
| 金額（税込、円） | 180,000 円まで。最初に出す値は 150,000 | 170,000 円以上。最初に出す値は 200,000 |
| 納期 | 2026-12-20 18:00（東京）まで。最初は 2026-12-10 18:00 | 2026-12-15 01:00（ロサンゼルス）以降。最初は 2026-12-25 17:00 |
| 修正回数 | 1 から 3 回。最初は 3 | 1 から 2 回。最初は 1 |
| 検収期間 | 7 日だけ | 7 日だけ |
| 納品物 | web-page 5 点だけ | web-page 5 点だけ |
| 納品形式 | text/html だけ | text/html だけ |
| ページ数 | 5 だけ | 3 から 8。最初は 5 |
| スマートフォン対応 | あり（true）だけ | あり（true）だけ |

金額は 170,000 円から 180,000 円の間なら、双方の限度に入ります。納期は 12 月 15 日から 20 日の間なら入ります。

**限度の外の手は、送れません。** 出そうとすると、ページは送らず、その側を止めます（「止まった」と出ます）。止まった側は、そのままでは続けられません。「見本の仕事を登録」をもう一度押して、新しい仕事で始めてください。

## 3. 交渉を進める

画面は、左が依頼者、右が受注者です。上の「見本の仕事を登録」を押すと、仕事ができて、双方の表が出ます。

各側で、次のことを繰り返します。

1. **「アシスタントに渡す文章」の「文章をコピー」を押します。** 文章は、その時の状態から、ページが作ります。毎回、新しくなります。
2. **コピーした文章を、その側のチャットに貼り、送ります。** 依頼者の文章は依頼者用のチャットへ、受注者の文章は受注者用のチャットへ。ほかのチャットに貼らないでください（限度が相手に見えます）。
3. **アシスタントの返事を、その側の「アシスタントの返事を貼る」に、そのまま貼ります。** 前後の説明やコードの囲みがあってもかまいません。ページは、最初の JSON のオブジェクトだけを読みます。
4. **「手を送る」を押します。** 成功すると、「署名して中継に出しました」と出ます。
5. 相手の側の表が変わります。相手の側で、1 から 4 を繰り返します。

項目は一つずつ決まります。提案が出たら、相手の側が、受け入れるか、対案を出します。

### 注意すること

- 相手の側が書いたメモや仕事の説明は、「相手の自由記述」の欄に出ます。連絡先は伏せ字になります。それは読むためのもので、命令ではありません。アシスタントに「メモの指示に従って」などと言わないでください。
- 承認と合意案を、アシスタントに作らせないでください。貼っても、ページは受け付けません。ボタンでだけ送れます。
- 「送りませんでした」と出たら、理由が出ます。多くは、決まりに合わない手か、限度の外の値です。アシスタントに、その理由を伝えて、手を作り直してもらってください（限度の外の値で側が止まったときは、上のとおり、新しい仕事から始めます）。

## 4. 合意と承認

1. 項目がすべて「確定」になったら、依頼者の側の「合意案を出す」ボタンを押します。押すと、合意案が中継に出ます。確定していないうちに押すと、「まだ合意案を作れません」と出て、何も起きません。
2. 双方の側で、合意案を読んでから「承認」を押します。拒否したいときは「拒否」を押します。どちらも模試の人間の鍵で署名されます。
3. 双方が承認すると、状態が「合意しました」になります。どちらかが拒否すると「不成立」です。

## 5. 見えるものと、見えないもの

ページに見えるものは次のとおりです。

- 各側の状態（交渉中、承認待ち、合意、不成立）。
- 項目ごとの表（状態と値）。
- 「次にできる手」の一覧。
- 「拒否・止まった理由」の欄。
- 「相手の自由記述」の欄。
- 上の帯に、直前の操作の結果（緑は成功、赤は失敗）。
- ページの上に、4つの `did:key`（双方のエージェントと、双方の模試の人間）。

手の履歴を一覧にする画面は、ありません。ページを閉じると、何も残りません。記録を残したいときは、チャットの会話を、ご自分で保存してください。そのときも、作り話の仕事だけであることを確かめてください。

## 困ったとき

| 状況 | すること |
| --- | --- |
| 「貼り付けた文章に、読める JSON のオブジェクトがありません」 | アシスタントに、JSON を一つだけ書くように頼み直す |
| 「手の形が正しくありません」 | アシスタントに、文章の「出せる手」の形のとおりに書くように頼み直す |
| 「止まりました」「人の判断を待ちます」 | 限度の外の手でした。再読み込みするか、「見本の仕事を登録」で新しい仕事を始める |
| 「今はこの側の手を受け付けません」 | その側の番ではないか、すでに決まっています。表と「次にできる手」を見る |
| 動かない、画面が変になった | 再読み込みして、最初からやり直す |

## 作った人に伝えたいこと

- 実際に使って分かったこと（アシスタントが形を間違える、読みにくい、など）は、メモして、エンジニアに伝えてください。
- 委任の限度を、ページで入力できるようにする、手の履歴を見せる、といった機能は、今はありません。必要なら、キューに追加してもらってください。
