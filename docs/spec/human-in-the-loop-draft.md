# 人と代理人が相談して決める方式（案）

状態: 案。ディレクターの方針（2026-11-14）を、今の仕様とコードに照らして書いたものです。実装はまだです。キューの Q11 から Q13 が、この案の続きです。

## 1. 方針（ディレクターが決めたこと）

- 代理人にすべてを任せません。**人と代理人が相談しながら、金額などの条件を決めます。**
- 流れは次のとおりです。
  1. 依頼票を探した代理人が、人に報告する。
  2. 人が条件を確認して、代理人に交渉を指示する。
  3. 代理人が、もう片方の代理人に打診する。
  4. 相手の返事を受けて、2 と 3 を繰り返す。
- 掲載と検索は、**もともとの仕様どおり、依頼票だけ**です。受託希望の一覧は作りません。仕事を頼む人がいなければ取引は成立しないので、依頼と受託希望が並ぶだけでは、マッチングになりません。
- **閉じ方は2つです。**
  - 片方が断ったとき。
  - 最後の打診から一定時間、返事がないとき（自動で閉じる）。
- 往復の上限は、**安全弁として残します。** 通常は無制限です。完全に自動で取引するときだけ、上限を付けます。
- **委任の限度は残します。** 限度の外の手は、人が指示しても、止めます。

## 3. 時間切れで閉じる規則（未決）

中継は時刻を確かめません。時刻は送り手の申告です（`ix-standard.md` 第9節、T25c）。そのため、「返事がない」ことを確実に決められるのは、打診した側が、自分の時計で見る場合だけです。

案（推奨）:

- 依頼票に、返事を待つ長さ（`silenceLimit`、時間の値）を持たせる。省略したら、時間切れでは閉じない。
- 最後に相手が手を出してから `silenceLimit` がたっても、相手の手がないとき、待っている側が `DealDecline` を出して、閉じる。理由は、新しい理由（例: `no_reply`）にする。
- 検証する側は、閉じる手の送り手が申告した時刻が、相手の最後の手の申告した時刻から `silenceLimit` 以上あとであることだけを確かめる。自分の時計は持たない（T27 と同じ）。
- 時間切れの閉じ方は、必ず、待っている側が自分で出す。相手を時計で閉じる、第三者の自動機構は、今は作らない。

未決の点（ディレクターの判断が要ります）:

- `silenceLimit` の長さ。依頼票ごとに、依頼する側が決めるのが自然です。
- 待っている側が、自分から閉じる手を出さなかった場合（閉じ忘れ）は、そのままにするか。

## 4. 往復の上限を省略できるようにする（未決）

- `roundLimitPerTerm` を、依頼票の省略できる欄にする。省略は「無制限」の意味にする。
- 完全に自動で取引するときは、依頼する側が値を入れる。
- 依頼票の内容のハッシュ（`anchor`）は、読み取る8つの欄で作られます。欄が省略できるようになると、省略したときの正規化のしかたを、決める必要があります（欄を入れない、という決め方が単純です）。
- 無制限の交渉は、時間切れ（第3節）だけが止め役になります。双方が返事を返し続ける限り、交渉は続きます。人が毎回判断する方式では、それが意図です。

## 5. 人の扉

次の変更は、人の扉に当たります。自動でマージしません（`AGENTS.md`）。

- 不成立の理由を足すこと、依頼票の欄を変えること、検証の規則を足すこと。
- 時間切れで閉じる手が、署名と承認の扱いに触れないこと。

Q11 と Q12 は、セキュリティレビュアーとディレクターの確認を前提にします。
