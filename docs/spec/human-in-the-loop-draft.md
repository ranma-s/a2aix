# 人と代理人が相談して決める方式（案）

状態: 案。ディレクターの方針（2026-11-14）を、今の仕様とコードに照らして書いたものです。実装はまだです。キューの Q11 から Q13 が、この案の続きです。

## 1. 方針（ディレクターが決めたこと）

- 代理人にすべてを任せません。**人と代理人が相談しながら、金額などの条件を決めます。**
- 流れは次のとおりです。
  1. 依頼票を探した代理人が、人に報告する。
  2. 人が条件を確認して、代理人に交渉を指示する。
  3. 代理人が、もう片方の代理人に打診する。
  4. 相手の返事を受けて、2 と 3 を繰り返す。
- 掲載と検索は、**もともとの仕様どおり、依頼票だけ**です。受託希望の一覧は作りません。仕事を頼む人がいなければ取引は成立しないので、依頼と受託希望が並ぶだけでは、マッチングになりません。
- **閉じ方は2つです。**
  - 片方が断ったとき（`DealDecline`）。
  - 最後の打診から **24 時間**、返事がないとき。**待つ側が閉じ忘れても、自動で閉じます。** 自動で閉じたことは、履歴に残します。
- 往復の上限は、**プロトコルにも依頼票にも入れません。** 交渉は、通常、無制限です。完全に自動で取引するときの安全弁は、各側の代理人の設定として持ちます（第4節）。
- **委任の限度は残します。** 限度の外の手は、人が指示しても、止めます。

## 3. 時間切れで閉じる規則

ディレクターの決定（2026-11-14）: これは時計の問題ではなく、**経過時間**の問題です。どの時計で測るかは、問いません。長さは **24 時間** です。待つ側が閉じ忘れても、**自動で閉じ、その履歴を残します。**

中継は時刻を確かめません。時刻は送り手の申告です（`ix-standard.md` 第9節、T25c）。そのため、規則は、メッセージに書かれた `sentAt` の差だけで決めます。時計を持たなくても、鎖を読めば、同じ結論になります（検証する側は、今も自分の時計を持ちません。T27）。

案:

- 長さは、プロトコルの決まった値（24 時間）にする。依頼票には、欄を足さない。
- 直前に適用されたメッセージの `sentAt` から、次のメッセージの `sentAt` までが 24 時間以上なら、その次のメッセージは断る。交渉は、直前のメッセージの `sentAt` に24時間を足した時点で、`no_deal`（理由 `silence`）として閉じていたと扱う。
- 次のメッセージが来ないまま、読む側の時計が、その時点を過ぎたとき、読む側（代理人や検証）は「閉じた」と扱う。誰かが閉じる手を出す必要はない。
- 閉じた履歴は、検証の報告と、各側の代理人の記録に出す。内容は、閉じた理由（`silence`）、最後のメッセージの鎖の指紋、最後の `sentAt`、閉じた時点（最後の `sentAt` + 24 時間）。
- 自動で閉じたことを、署名つきの中継の記録としても残すかは、未決（下の「未決の点」）。

未決の点（Q11 で決めます）:

- 承認待ち（`awaiting_approval`）の間にも、24 時間の規則をかけるか。人の承認は、返事に時間がかかります。案は、交渉中（`negotiating`）だけにかけ、承認待ちには、別の限り（今は依頼票の期限）を使う。
- 閉じた履歴を、検証の報告だけにするか、署名つきの中継の記録（新しい種類の記録。人の扉です）としても残すか。案は、まず検証の報告と代理人の記録だけにする。
- 「最後の打診」を、最後のメッセージ全部と読むか、返事を待つ手（提案、対案、追加などの要求）だけと読むか。案は、最後のメッセージ全部（単純で、鎖だけで決まる）。

## 4. 往復の上限

ディレクターの決定（2026-11-14）: 往復の上限の欄は、入れません。

- `roundLimitPerTerm` を、依頼票から外す。交渉の機械は、往復を数えず、往復の上限による不成立（`round_limit`）と、任意の項目の取り外しをなくす。
- 依頼票の内容のハッシュ（`anchor`）は、7つの欄で作る（欄が1つ減る）。
- 往復が続く限り、交渉は続く。止め役は、返事の途絶えの24時間（第3節）と、依頼票の期限と、どちらかの辞退。
- 完全に自動で取引するときの安全弁は、各側の代理人の設定として持つ（例: 1つの項目で N 回を超えて対案が続いたら、代理人が自分から `DealDecline` を出す）。プロトコルの決まりではなく、代理人の振る舞いです。

確認が要る点: 「欄を入れない」を、「プロトコルから往復の上限をなくし、安全弁は代理人の設定にする」と読みました。違う読み方（例えば、依頼票には欄を置かず、機械の中に決まった上限を持つ）なら、教えてください。

## 5. 人の扉

次の変更は、人の扉に当たります。自動でマージしません（`AGENTS.md`）。

- 不成立の理由を足すこと、依頼票の欄を外すこと（ハッシュの入力が変わる）、検証の規則を足すこと。
- 時間切れで閉じる手が、署名と承認の扱いに触れないこと。

Q11 と Q12 は、セキュリティレビュアーとディレクターの確認を前提にします。

## 6. 進め方

- Q11: この案を、仕様の文章（`ix-standard.md` に載せられる形）にして、決めきれていない点を決める。実装はしません。
