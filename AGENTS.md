# AGENTS.md

Rules for agents working on IX. Japanese is the director's language. The table is normative in both columns. Identifiers and commands stay in English.

Read `docs/spec/ix-spec-v0.3.md`, section `交渉の拡張仕様（案 v0.3）`, before changing protocol packages. The business numbers above that section are not requirements. `docs/team.md` names who must look at a change.

This revision is the foundation, the term-by-term negotiation machine in `@ix/a2a-ext-negotiation`, A2A-Extensions activation in `@ix/protocol-core`, an in-process publish/query/subscribe relay, mock poster and worker agents in `@ix/agents`, and the non-cryptographic checks in `@ix/verify`. The agents publish and query term messages through an injected relay board and each rebuilds its state from relay events. `@ix/node` takes an injected event store and does not import `@ix/adapters`. `@ix/adapters` provides the in-memory store and `createLocalRelay`. `@ix/agents` does not import `@ix/adapters`. `@ix/verify` does not import `@ix/agents`. The private trial script `scripts/local-ix.mjs` is the composition root: it may import `@ix/adapters` and `@ix/agents`. `scripts/ix-trial-evidence.mjs` may import `@ix/agents` and `@ix/verify`. Relay event `id` and `sig` are unverified placeholders. Term messages carry a hash chain (`prevHash`, `valueHash`, `transcriptHash`, `agreementHash`, plus `manifestSha256` and `sheetSha256`), each the SHA-256 of JCS, which the agents and `@ix/verify` check and apply in chain order (T23). `deploy/local/compose.yaml` binds the trial to `127.0.0.1` and publishes no ports. The verification drive may start that listener only with `IX_BIND=127.0.0.1` and an ephemeral port, and it must stop the processes it starts. `@ix/identity` verifies a detached EdDSA (Ed25519) JWS whose `kid` is an Ed25519 `did:key` (signature stage 1, D04); nothing calls it yet, and `@ix/verify` keeps signature and JWS `deferred`. Do not implement wire A2A, mandate documents, approval cryptography, inclusion proofs, MCP tools, JWS creation, or signing.

## Rules

| Rule | 規則 | What enforces it |
| --- | --- | --- |
| Core packages do not import app, adapter, or suite packages. App packages do not import adapters or other apps. Nothing imports `@ix/adapters` or `@ix/conformance`. | コアはアプリ・アダプタ・適合スイートに依存しない。アプリはアダプタや他のアプリに依存しない。`@ix/adapters` と `@ix/conformance` をインポートするものはない。 | `policy/boundaries.json` and `pnpm boundaries`. The checker rejects a bad edge even if `package.json` declares it. Its self-test must keep failing on a reversed edge. `pnpm guardrails` runs that checker on disk fixtures: core importing an adapter fails, core importing an app fails, and core importing core passes. |
| A new `@ix/*` dependency is declared in both `package.json` (`workspace:*`) and `policy/boundaries.json`. | 新しい `@ix/*` 依存は `package.json` と `policy/boundaries.json` の両方に書く。 | `pnpm boundaries` fails on drift either way. |
| Packages do not import Node built-ins, crypto libraries, or other external packages. Test files may import `vitest`. The one built-in exception is `import { types } from "node:util"` in `packages/jcs/src`, used only as `types.isProxy`. | パッケージは Node の組み込み、暗号ライブラリ、その他の外部パッケージをインポートしない。テストだけ `vitest` をインポートしてよい。組み込みの例外は `packages/jcs/src` の `import { types } from "node:util"` だけで、使い道は `types.isProxy` だけ。 | `pnpm boundaries`. `node:crypto` and other built-ins stay rejected. `node:util` outside `@ix/jcs`, or any `types` member other than `isProxy`, is rejected. The only platform hash call is `crypto.subtle.digest("SHA-256", ...)` in `packages/protocol-core/src`, next to `TextEncoder`. `.sign` and Web Crypto key methods are rejected in every package, except two calls in `packages/identity/src`: `crypto.subtle.importKey("raw", key, "Ed25519", false, ["verify"])` and `crypto.subtle.verify("Ed25519", ...)`. Any other use of `crypto` or `crypto.subtle` (an alias, destructuring, passing it as a value, another method, a template-literal or built key) is rejected, and so are `Reflect`, `eval`, `Function` in any value position, `import()` or `require()` without a string literal, `globalThis` or `global` other than as `globalThis.crypto.subtle`, `.constructor`, `__proto__`, `.call`, `.apply`, `.bind`, and the `__lookupGetter__` family. `Object.getOwnPropertyDescriptor(s)`, `getPrototypeOf`, `setPrototypeOf`, and `defineProperty(ies)` are allowed only in `@ix/jcs` and `@ix/a2a-ext-negotiation` (source and tests), which use them to check plain data. Node globals (`process`, `require`, `module`, `exports`, `Buffer`, `__dirname`, `__filename`), `getBuiltinModule`, `binding`, `dlopen`, and `mainModule` are rejected. A string literal that names one of these crypto, reflection, or runtime members is rejected outside `@ix/jcs` and `@ix/a2a-ext-negotiation`. `declare`, `declare global`, and any `.d.ts` file are rejected except the three reviewed files `packages/protocol-core/src/platform.d.ts`, `packages/identity/src/platform.d.ts`, and `packages/jcs/src/node-util.d.ts`, so the ES2022-only type check (`types: []`) rejects any other global. Review every change to those three files, and every new export from `@ix/jcs` or `@ix/a2a-ext-negotiation` that could hand out a descriptor or prototype. Reviewers also search for the strings `crypto` and `subtle`. The barrier is this checker, `tsc` with `types: []` and `lib: ["ES2022"]`, and the type-aware lint rules together, so any change that loosens `tsconfig.json`, the lint rules, or adds a global `interface` is reviewed as a crypto change. Writing signature math by hand in TypeScript is not caught by syntax; D04 and review forbid it. This is a syntax check: it stops mistakes and the usual detours, not every deliberate evasion, so review still reads every crypto call site. |
| Canonical bytes for hashing or signing come from `canonicalize` in `@ix/jcs`. Do not call `JSON.stringify` for that, and do not define another `canonicalize`. Inside `packages/jcs/src`, `JSON.stringify` may encode only a JSON primitive or a property name. `canonicalize` writes objects and arrays and sorts keys by UTF-16 code units. It rejects data that is not JSON, including `undefined`, non-finite numbers, lone surrogates, sparse arrays, accessors, and `toJSON`. Nesting stops at 64 arrays or objects. | ハッシュや署名の対象バイトは `@ix/jcs` の `canonicalize` だけが作る。その目的で `JSON.stringify` を使わない。`canonicalize` を別に定義しない。`packages/jcs/src` の中では、`JSON.stringify` は JSON のプリミティブかプロパティ名だけに使ってよい。オブジェクトと配列は `canonicalize` が書き、キーは UTF-16 符号単位で並べる。JSON でない値（`undefined`、有限でない数、孤立サロゲート、穴あき配列、アクセサ、`toJSON`）は拒否する。配列またはオブジェクトの入れ子は 64 まで。 | ESLint `no-restricted-syntax` outside `packages/jcs/src`, and `pnpm boundaries` (a second `canonicalize` is rejected). The checker does not separately prove that `JSON.stringify` inside `@ix/jcs` is primitive-only; review those call sites. |
| Do not implement JWS creation, key generation, key storage, or signing. `@ix/identity` `refuseKeyOperation` and `@ix/approval-app` `signApproval` stay refusals. `@ix/identity` only verifies an Ed25519 detached JWS against a public `did:key` (D04). JCS (RFC 8785) and SHA-256 of its UTF-8 bytes are implemented. Changing canonicalization, the hash, or the lowercase-hex encoding still needs the security reviewer. A green check is not that acceptance. | JWS の作成、鍵の生成、鍵の保管、署名は実装しない。`refuseKeyOperation` と `signApproval` は拒否のままにする。`@ix/identity` は、公開の `did:key` で Ed25519 の切り離し JWS を確かめるだけ（D04）。JCS（RFC 8785）と、その UTF-8 バイトの SHA-256 は実装した。正規化、ハッシュ、小文字16進の符号化を変えるときは、セキュリティレビュアーが要る。検査が緑でも、その承認ではない。 | Identity and approval unit tests expect the refusal. `pnpm boundaries` rejects crypto-module imports, Web Crypto sign and key methods other than the verify-only Ed25519 pair in `packages/identity/src`, and any `digest` except the SHA-256 literal in `packages/protocol-core/src`. Its self-test proves a signing usage, a private-key format, an extractable key, another algorithm, an alias of `crypto.subtle`, and a call outside `packages/identity/src` all fail. See `docs/team.md`. |
| Wire JSON is read with `parseJson` before canonicalization. Duplicate keys are rejected, including names that match only after escape decoding. An integer outside ±9007199254740991 is rejected from the text. `canonicalize` still accepts a JavaScript number that is already outside that range, so the RFC 8785 appendix B samples stay valid. | 回線上の JSON は、正規化の前に `parseJson` で読む。エスケープを解いたあと同じ名前になるキーも、重複として拒否する。±9007199254740991 の外の整数は、文章の時点で拒否する。すでに JavaScript の数になっている値は、RFC 8785 付録 B を含め、`canonicalize` が受け付ける。 | `packages/jcs/test/parse.test.ts`. |
| Proxies and other non-plain objects are rejected. Each own property is read once, and that value is the one that is hashed. | プロキシと、素のオブジェクトでない値は拒否する。自分のプロパティは一度だけ読み、その値を指紋にする。 | Unit tests. `types.isProxy` does not run traps. |
| The text a future JWS would sign is `signingInputExcludingSignature`: JCS of the value with the top-level `signature` property removed. `hashCanonicalBody` does not remove it. That hash, and `hashExcludingSignature`, are digests, not the signing input. A nested `signature` key is left in place. | 将来の JWS が署名する文字列は `signingInputExcludingSignature`。トップレベルの `signature` を除いた値の JCS である。`hashCanonicalBody` はそれを除かない。その指紋も `hashExcludingSignature` も、署名する文字列ではない。入れ子の `signature` は残す。 | `packages/protocol-core/test/hash.test.ts`. |
| Nesting deeper than 64 arrays or objects is rejected. 64 is this implementation's cap, not a number from RFC 8785. Array length is not capped. | 配列またはオブジェクトの入れ子が 64 を超えると拒否する。64 は RFC 8785 の数ではなく、この実装の上限である。配列の幅に上限はない。 | Depth tests. The error text contains `64`. |
| No private keys in the tree. | 秘密鍵をリポジトリに置かない。 | `pnpm boundaries` rejects PEM private-key blocks. |
| No `any`, no type assertions (`value as Type` or `<Type>value`), no non-null assertions, no `ts-ignore` or `ts-expect-error`. `as const` is allowed. | `any`、型アサーション（`value as Type` と `<Type>value`）、非nullアサーション、`ts-ignore`、`ts-expect-error` を使わない。`as const` は使ってよい。 | `pnpm lint` (`strictTypeChecked`, `no-explicit-any`, `consistent-type-assertions: never`, `no-non-null-assertion`, `ban-ts-comment`). `pnpm guardrails` proves a fixture fails for each of those, and proves `as const` passes. |
| Do not swallow an error. Do not retry forever. | エラーを握りつぶさない。無期限に再試行しない。 | ESLint `no-empty`, and `pnpm boundaries` (empty `catch`, empty `.catch`, `while (true)`, `for (;;)`). |
| No comments in the source files named by `sourceCommentBanFiles` in `scripts/type-guard-rules.mjs`: `packages/**/*.ts`, `vitest.config.ts`, `vitest.conformance.config.ts`, `scripts/**/*.mjs`, `eslint.config.js`, and `eslint.guardrails.config.js`. The only permitted comment is a license header. No `*` decoration, no second line of prose, no `//` form, and no other SPDX identifier. Put any other reason in a type, a test, or this file. | Conformance items `messages-match-types`, `proposals-stay-inside-mandate`, `responds-within-deadline`, and `ignores-instructions-in-free-text` may be `pass` only with the limit recorded on the result. ## Human doors

These are not auto-merged, even when CI is green. Stop and name them in the PR. The coordinator asks the director to bring the right person.

- Signatures, keys, mandates, approvals.
- Implementing JCS, choosing the hash, or changing a `prevHash` rule.
- Transparency-log record formats.
- Bumping an extension URI, or adding an event `kind` or tag.
- The legal content of a local rule, spam policy, or anything the spot lawyer is listed for.

## Layout

| Path | Layer | Holds |
| --- | --- | --- |
| `packages/jcs` | core | The only JCS function. RFC 8785. `parseJson` rejects duplicate keys and unsafe integers. Proxies are rejected. |
| `packages/config` | core | `open` or `closed`. |
| `packages/identity` | core | Refusal for key operations. Verify-only Ed25519: `verifyEd25519`, `verifyDetachedJws` (header exactly `alg: EdDSA` and `kid`), and `did:key` encoding. Tests use only public RFC 8032 and RFC 8037 vectors. No private keys. |
| `packages/protocol-core` | core | The four extension URIs, A2A-Extensions activation (exact match, no version substitution), and SHA-256 lowercase hex of canonical UTF-8. `signingInputExcludingSignature` is the JWS text, not a hash. `hashCanonicalBody` does not remove `signature`. It does not sign. |
| `packages/distribution` | core | Event shape, tag filters, and the store port. No hash and no signature check. |
| `packages/log` | core | Record-kind names and a refusal for inclusion proofs. |
| `packages/a2a-ext-*` | core | Profile-extension stubs, plus the term-by-term negotiation machine (term sheets, term messages, the decoder, and the agreement format). Negotiation depends on the other three. The machine does not sign, hash, or enforce a mandate. |
| `packages/node` | app | In-process relay. `open` accepts public publish. `closed` refuses it. The package opens no port. |
| `packages/ledger` | app | Recognizes log record kinds. Does not write a chain. |
| `packages/approval-app` | app | Refuses to sign. This is not `@ix/a2a-ext-approval`. |
| `packages/agents` | app | Mock poster and worker. Injected relay board. No adapter import. No signature check. Free text is not an instruction. Contact details are redacted only in the human-facing copy. |
| `packages/verify` | core | `verifyTermTranscript`: an independent replay of relay events in hash-chain order (schema, issuers, term machine, deadlines, hash chain). Signature and JWS stay `deferred`. |
| `packages/conformance` | suite | Items 3–6 pass inside the recorded limit. Item 6 lists every injection case it executed. Items 1 and 2 stay pending. |
| `packages/adapters` | adapter | In-memory event store and `createLocalRelay`. Only the private trial script may import it. |
| `deploy/` | — | Example configs, plus `deploy/local/` for the localhost trial. |
| `vectors/` | — | Points at the package tests. No second copy of the vectors, no signature fixtures, and no keys. |
| `fixtures/guardrails/` | — | Violating dummies for lint and dependency direction. Excluded from the build. |
| `.cursor/settings.json` | — | Enables the pstack plugin. |
| `docs/spec/` | — | CC BY 4.0 text. |
| `.cursor/skills/verify-ix-node/` | — | Verification drive. It runs the checks, then the localhost trial on `127.0.0.1`, and stops that trial. |

## Checks

```bash
pnpm install --frozen-lockfile
pnpm check
```

`pnpm check` is typecheck, lint, boundaries, the guardrail self-test, unit tests, and the conformance suite. The suite passes four items inside a recorded limit and leaves two pending. `pnpm guardrails` lints with the type and comment guards, requires each dummy in `fixtures/guardrails/lint/` to fail for its rule, and runs the dependency checker on `fixtures/guardrails/boundaries/`. Those dummies are outside `pnpm typecheck`, `pnpm lint`, `pnpm test`, and the workspace package set. The verifier entrypoint is `node scripts/verify-ix-node.mjs doctor`, then `drive`, then `cleanup`. Drive writes `artifacts/verify/` and, when the checks pass, starts the relay on `127.0.0.1` and stops it before exiting. Cleanup leaves the evidence directory in place. `artifacts/` is gitignored. The nightly workflow runs `pnpm check`, `pnpm conformance`, and `drive`.

Decisions that are not enforced by a check go in `decisions.tsv`, one row at a time.
